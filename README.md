# PCB Defect Inspector

An end-to-end computer-vision system for bare-PCB quality control.

**Image in -> YOLO detects defects -> a vision-language model double-checks the uncertain ones -> a RAG-grounded report explains what to do -> served as a REST API + web UI in Docker.**

Trained on the public PKU-Market-PCB dataset (6 defect types: missing_hole, mouse_bite, open_circuit, short, spur, spurious_copper). Training runs on a free Kaggle GPU; serving runs on CPU in Docker (ONNX Runtime) with a local Ollama model, so it needs **no paid API keys**.

## Step 0: 5-minute smoke test (recommended)

Proves every stage runs on fake data before you spend GPU time. Needs Python 3.10+ and `pip install -r requirements.txt` (CPU is fine, it downloads the small `yolov8n.pt`).

```bash
pip install -r requirements.txt
python -m pytest -q tests            # 26 tests, no GPU needed
python scripts/smoke_test.py         # synthetic data -> train 3 epochs -> ONNX -> pipeline
```

## Step 1: Train on Kaggle (free GPU)

1. Zip this folder. On Kaggle: **Datasets -> New Dataset**, upload it, name it **`pcb-inspector-code`**.
2. New Notebook -> **File -> Import Notebook** -> upload `notebooks/kaggle_train.ipynb`.
3. Right sidebar: **Accelerator = GPU T4 x1**, **Internet = On**.
4. **Add Input** -> search `pcb-defects` (by *akhatova*) and add it; also add your `pcb-inspector-code` dataset.
5. First do a dry run with `EPOCHS = 5`, then set `EPOCHS = 80` and **Run All** (roughly 1 to 1.5 hours on a T4; lower `BATCH` to 4 if you hit out-of-memory).
6. From the notebook's **Output** tab download `pcb_artifacts.zip`.

The dataset size is described differently by different sources (1386 images on Kaggle, 693 original boards in papers). The converter prints exactly what it found (pairs, skipped rotated copies, class counts), and by default **ignores rotated/augmented folders** so near-duplicate images cannot leak between train and test. Check the printed counts.

## Step 2: Bring the model home

Unzip `pcb_artifacts.zip` into the project: `models/best.pt`, `models/best.onnx`, `models/model_meta.json` go to `./models/`, and `reports/*` to `./reports/`. Open `reports/evaluation_report.md` for your real mAP, per-class table, confusion matrix and worst cases.

## Step 3: Run it (Docker, CPU)

**Full stack with the local VLM** (first start downloads the Ollama model, about 3.2 GB, into a Docker volume):

```bash
cp .env.example .env
docker compose --profile ollama up --build
```

**Lite stack** (no model download; the VLM is replaced by a mock, reports use the template): set `VLM_PROVIDER=mock` in `.env`, then

```bash
docker compose up --build
```

Open:
- UI: http://localhost:8501
- API docs (Swagger): http://localhost:8000/docs
- Health: http://localhost:8000/health (tells you if weights or the VLM are missing)
- Metrics: http://localhost:8000/metrics

To reclaim disk later: `docker compose down -v` (removes the model volume).

**Which VLM model?** Set `OLLAMA_MODEL` in `.env`. Default `qwen2.5vl:3b` (about 3.2 GB, needs roughly 8 GB free RAM given to Docker). If your machine is short on RAM, try `moondream` (smaller and weaker). CPU inference takes tens of seconds per call, which is why only uncertain detections are sent to it (max `VLM_MAX_CALLS`, default 3). Use the UI's "template" report mode for instant reports.

## Step 4: Measure whether each part earns its place

```bash
# does the VLM second opinion actually help? (run locally with Ollama up, or set VLM_PROVIDER=gemini)
python -m src.training.evaluate_pipeline --data dataset/data.yaml --limit 40
# ONNX vs PyTorch latency on CPU
python -m src.optimization.benchmark --models models/best.pt models/best.onnx --images dataset/images/test
```

`reports/pipeline_ablation.md` compares: detector only, high-confidence only, + VLM rejects, + VLM relabels. **A 3B model may hurt more than it helps on tiny PCB defects.** If variant C/D do not beat A on F1, keep `VLM_POLICY=flag` (the VLM only marks disagreements for human review), which is the safe default. Reporting that honestly is a stronger interview story than claiming the VLM always helps.

## Configuration (env vars / `.env`)

| Variable | Default | Meaning |
|---|---|---|
| `MODEL_PATH` | `models/best.onnx` | weights (falls back to `best.pt`) |
| `CONF` / `IOU` | 0.25 / 0.5 | detector threshold / NMS IoU |
| `VLM_PROVIDER` | `ollama` | `ollama`, `gemini`, `mock`, `none` |
| `OLLAMA_MODEL` | `qwen2.5vl:3b` | any vision model in Ollama |
| `VLM_GATE_CONF` | 0.5 | detections below this go to the VLM; also the FAIL threshold |
| `VLM_MAX_CALLS` | 3 | VLM calls per image (latency cap) |
| `VLM_POLICY` | `flag` | `flag` = disagreement marks REVIEW; `apply` = VLM may drop/relabel |
| `REPORT_MODE` | `llm` | `llm` (auto-falls back to `template`) or `template` |
| `GEMINI_API_KEY` | empty | only for `VLM_PROVIDER=gemini` |
| `LOG_REVIEW_IMAGES` | true | keep REVIEW images in `logs/review_queue/` for error analysis |

## Troubleshooting

- **`No model weights found` / `/health` returns 503:** copy `best.onnx` (or `best.pt`) into `./models/`.
- **UI says "Ollama model not ready":** the first start is still pulling the model (`docker compose logs -f ollama-pull`). The app works meanwhile (VLM step is skipped, template report).
- **CUDA out of memory on Kaggle:** `BATCH = 4`, or `IMGSZ = 896`, or `MODEL = "yolov8n.pt"`.
- **No image pairs found:** check the printed scan stats; point `--src` at the folder that contains the XML files; use `--exclude ""` to disable the rotation filter.
- **ONNX export complains about `onnxslim`:** `pip install onnxslim`, or edit `simplify=False` in `export_onnx.py`.
- **Gemini model name rejected:** set `GEMINI_MODEL` to a current model from Google AI Studio.

## Limitations and next steps

- The dataset is small and synthetic-looking (bare boards, clean backgrounds). Expect a domain gap on real factory images; the `review_queue` is the start of an active-learning loop.
- Images are resized to 1024 px; very tiny defects may need **tiled inference** (SAHI-style) to improve recall.
- `--quantize` (dynamic int8) is experimental; always re-run `evaluate.py` on the quantized model.
- On a GPU host you could swap ONNX Runtime for TensorRT.
